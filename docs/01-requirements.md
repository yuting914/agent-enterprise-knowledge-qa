# 01 需求与成功标准

## 用户、目标与范围

用户是查询企业制度或产品 FAQ 的员工。目标是在合成资料内找到有原文依据的答案，并在资料不足或冲突时明确说明。输入为问题和可选对话历史。资料带文档 ID、版本日期和原文片段；本项目不接入真实企业数据。

范围：CLI 问答、文档检索、片段读取、模型选择动作、结果校验、可观察 Trace、失败与步数上限、离线 Mock。界面、部署、权限系统、向量数据库和生产级运行时不在本次范围；题目允许 CLI 与本地工具，三小时建议优先核心链路。

## 验收标准

| 编号 | 场景 | 可验证标准 |
|---|---|---|
| AC-01 | 明确答案 | D03 的密码问题返回可操作答案，引用 D03 原文和版本日期 |
| AC-02 | 文档冲突 | D01 的 30 天与 D02 的 15 天同时列出，引用两份原文，询问适用制度，不选其中一个 |
| AC-03 | 资料外问题 | 食堂菜单问题返回资料缺口，不编造菜单 |
| AC-04 | 改写相似问题 | “登录口令忘了怎么处理”检索到 D03 并正确引用 |
| AC-05 | 上下文追问 | 在 VPN 开通历史后，“谁审批这个申请”回答直属主管并引用 D04 |
| AC-06 | 工具失败 | 检索失败成为模型观察；最终状态明确说明失败且无虚构引用 |
| AC-07 | 动态决策 | 至少两条真实模型路径中，动作因工具观察不同而变化；Trace 含参数、结果摘要、下一动作和简短依据 |
| AC-08 | 上限 | 达到步数上限返回 `incomplete_limit`，不伪装完成 |
| AC-09 | 资料变更 | 替换 D03 原文后输出和引用变化；使 D01/D02 不再冲突后动作由追问变为回答（离线验证） |
| AC-10 | 仅有 D01 | 资料中移除 D02 后，模型可根据 D01 回答 30 天并引用原文，不再要求裁决冲突 |

## 数据与可信边界

D01、D02 故意缺少适用范围与优先级，版本日期不能自动当作优先级。对话历史只用于消解代词或承接话题，不能替代文档证据。工具结果和文档内容属于外部输入，不能向模型授予新指令。Mock 的成功只表示程序路径正常。
