# 05 复盘

## 最难问题

最难的是让真实模型运行证据可重复且不把 Mock 结果伪装成模型决策。最初 Codex CLI 连续连接超时；改用已登录的 Claude Code CLI 后，发现模型可能在检索前直接宣告资料不足、或在追问动作里留空正文。加入了最小输出校验和反馈循环。模型服务曾返回 `402 Insufficient Balance`，用户充值后补齐了真实模型运行记录。复跑时还发现超时异常会回显完整命令与问题，随后改为只记录简短超时状态。

## 学习与改进

- 把检索结果与原文读取拆开，能看到模型是否真的查证。
- 只验证引用字符串仍不够；还需人工判断答案与引用的语义关系。
- 冲突资料不能凭较新日期自动裁决；范围和优先级缺失时必须追问。
- 运行环境报告的实际模型可能与请求别名不同，应记录两者。
- 对照评审参考实例再补一份 D01 单文档语料，真实复验了冲突消失后由追问改为直接回答，并记录语料哈希，避免只凭 Mock 推断模型效果。

## 下一步

若扩展到企业资料，先做检索召回基线、文档权限过滤、更新与版本策略，再考虑向量索引和服务化。真实模型复验应在资料或提示变化后重新运行，不能把保存的 Trace 当成未来运行保证。
